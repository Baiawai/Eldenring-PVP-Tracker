# Construction et examen Store

La préparation actuelle ne constitue pas une version prête à soumettre. L'ancien classement distant reste désactivé. Le code Store en préparation utilise exclusivement `https://eldenringpvp.com` pour le nouveau classement et ignore les autres adresses configurées localement ; la participation nécessite un consentement et une connexion Steam vérifiée. Dans l'application, les profils du classement s'affichent après acceptation des conditions. Les opérations en attente sur un ancien serveur restent conservées et ne sont pas envoyées depuis la version Store. Le tag GitHub `v1.0.3.0` et les packages déjà construits peuvent différer de ce code : vérifier le contenu et la version du package réellement soumis avant de rédiger ses notes. Dans la version compilée, la mesure avec élévation est désactivée : seul le ping disponible auprès de Steam est affiché ; il peut être indisponible. La version de développement permet la mesure avancée avec autorisation administrateur. Vérifier les droits sur les ressources du jeu, les images, polices, données et toutes les licences des dépendances redistribuées, notamment les DLL Tesseract.

Sur Windows x64, installer Python 3.15, créer `.venv`, installer `requirements.txt` puis `pyinstaller==6.22.3`. Installer le SDK Windows avec MakeAppx. Exécuter `.\.venv\Scripts\python.exe store\prepare_tesseract.py` pour préparer Tesseract 5.5.4 et ses dépendances dans `build/tesseract-5.5.4` : le développement et la compilation Store utilisent tous deux cette distribution en priorité. Sinon, le script utilise `C:\Program Files\Tesseract-OCR` ; `-TesseractDir` permet de choisir une autre distribution complète avec ses licences. Les modèles OCR du projet sont embarqués. La compilation n'inclut pas les captures personnelles présentes dans `application`.

Au démarrage, une installation signée par le Microsoft Store vérifie si le Store lui propose une mise à jour du package principal. Si oui, le tracker affiche un écran demandant la mise à jour et ne démarre pas le suivi. Une erreur, une indisponibilité du Store ou une expiration du délai laisse l'application accessible hors ligne. La version de développement et les packages non signés par le Store ne sont pas concernés. La disponibilité dépend du déploiement et du cache du Store ; tester cette fonction avec une installation Store réelle avant publication.

Après réservation du nom dans Partner Center, reprendre exactement le nom d'identité du package, le sujet Publisher et le nom d'éditeur communiqués par Partner Center :

```powershell
.\store\build.ps1 -Identity 'IDENTITE_PARTNER_CENTER' -Publisher 'CN=SUJET_PARTNER_CENTER' -PublisherDisplay 'NOM_EDITEUR' -Version '1.0.4.0'
```

La version par défaut du script est `1.0.4.0` ; avant une soumission, vérifier dans Partner Center que le numéro choisi est supérieur à celui de la version déjà publiée. Le fichier MSIX non signé est créé dans `dist/store/`. Les options `-OutputDir` et `-WorkDir` permettent de construire dans des dossiers séparés pour conserver les paquets précédents. `-ExecutableOnly` construit uniquement l'exécutable et ses ressources. Une signature de test et un certificat approuvé sont nécessaires pour tester l'installation sur une machine ordinaire ; Microsoft signe le package publié après certification. Tester l'installation, le démarrage, les mises à jour, la désinstallation, les modes de suivi et la capture en plein écran avec Steam et le jeu avant la soumission. Ne pas lancer l'exécutable parallèlement à un tracker actif, car les deux utilisent le port 5000.

Le contrôle `.\.venv\Scripts\python.exe store\smoke_test.py` utilise un APPDATA temporaire et interroge l'interface sans ouvrir de port. Il nécessite l'accès à WMI ; il ne remplace pas un essai de capture en jeu ou du package installé.

Renseigner la fiche Store, ses captures et une URL publique de politique de confidentialité. Celle-ci doit décrire les captures d'écran, les données conservées localement (dont historique Steam et adresses IP éventuelles), et l'identifiant construit à partir de l'adresse MAC et du nom de machine. Vérifier les données effectivement transmises, leurs destinataires et durées de conservation. L'application utilise un serveur HTTP sur localhost et possède des routes de modification : examiner leur protection contre les requêtes non sollicitées d'autres pages locales ou sites web avant publication. L'installation MSIX peut isoler ou rediriger les données existantes : tester la migration et la désinstallation sur une copie, sans toucher aux données réelles.
